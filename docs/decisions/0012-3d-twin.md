# 0012. 3D digital twin view: Blender bake + three.js (React Three Fiber)

Status: accepted (2026-10-10). Supersedes [0006](0006-no-3d-twin.md).

## Context

ADR 0006 rejected a 3D twin, partly because the dev PC seemed to have only Intel graphics. In fact it has an **NVIDIA RTX 4060 Laptop GPU (8 GB)**, which was disabled. Role B (who owns the twin) wants a high-realism 3D view built entirely from code.

## Decision

- **Not Omniverse or Unreal.** They need an RTX card on every viewing machine (Omniverse), or most of the work happens in a graphical editor that can't be done from code (Unreal).
- **Blender**, driven by Python (`bpy`) scripts, builds the ward from `seed/ward-W1.yaml`.
  - Free CC0/CC-BY models and Poly Haven textures.
  - **Lighting baked with Cycles on the RTX 4060 (OptiX)**.
  - Exported as compressed `.glb` (Draco geometry, KTX2 textures).
- **`apps/twin3d`** (React Three Fiber + drei + postprocessing) renders it live:
  - HDRI lighting, ambient occlusion (N8AO), bloom, AgX tone mapping.
  - Animated nurses (Mixamo).
  - Quality adapts to the machine's GPU.
  - A path-traced photo mode for the pitch slides.
- **Display only.** It reads the same WebSocket stream as the board, and stale data looks stale in 3D too (safety invariant 5).
- Asset licences go in `apps/twin3d/CREDITS.md`. No brand logos, no real people.

## Consequences

- It is **polish, off the critical path** (Track 2 scores coordination, resilience and latency). It is built after the Must and Should items work.
- The 2D floor plan on the board remains the reliable view the demo depends on.
- Owner: B.
